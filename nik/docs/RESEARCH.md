# Research notes: what makes a ~20M model reason

Nik is small on purpose. These are the levers we use, why each one is there, and how we measure it. Every reply in `/chat` is sampled from the network: there are no scripted replies, retrieval, or calculator tools.

## 1. Data is the model (coherence)

The first CPU preview babbled. The cause was the data, not the model: the news dataset stores one *headline per row*, and we had packed neighbouring rows into documents. The model faithfully learned to change topic mid-sentence.

- Each news row is now its own document, and rows under 160 characters are dropped.
- **Synthetic stories and explanations** (`data/gen_stories.py`): 80k short, causally connected stories (character → goal → problem → help → resolution → moral) and topic explanations in romanized Nepali. TinyStories (Eldan & Li, 2023) showed that models of a few million parameters write coherent text when part of their diet is simple and consistent. Real text alone is too dense for them.
- **Open-ended writing SFT.** The targets are real Wikipedia paragraphs, so "write about X" teaches *writing*, not recall.

## 2. Numbers: abacus digit embeddings

Transformers lose track of which digit is in which column: the position of a digit within its number is not visible to them. **Abacus embeddings** (McLeish et al., *Transformers Can Do Arithmetic with the Right Embeddings*, NeurIPS 2024) add a learned vector for each digit's index inside its number. With them, small transformers reach near-perfect multi-digit addition and generalize to longer numbers.

Our implementation (`NikLM.digit_index`, mirrored in `nik.js`):
- The tokenizer guarantees that digits are single tokens: `" 4"` starts a number and `"4"` continues one.
- The index is computed causally with a cumulative max over run starts. It depends only on past tokens, so it works with the KV cache and needs no lookahead.
- In the two-stream hybrid loss, indices are computed **per stream**, so a digit run never continues across the noisy/clean seam. Masked digits get index 0, exactly as at inference.
- Row 0 is a zero padding row. Python and JS agree exactly (max logit difference 0.00000 on the f32 path).

## 3. Reasoning traces that check themselves

Every math and word-problem trace has the same shape:

```
dieko (given): pahila 15, thap 7.  sodheko (asked): jamma.  thap bhaneko jodnu (op).
15 + 7 = 22.  jaach (check): 22 - 7 = 15 ✓
```

Column arithmetic is written place by place with explicit carries and borrows ("ek ko thau: 7 + 8 = 15, 5 rakhne, 1 hasil"). Each step is a *local* computation a small network can learn, and the final check trains the model to verify, not just assert. Step-by-step training data is the most reliable known way to give small models multi-step skills (Lee et al., *Teaching Arithmetic to Small Transformers*, 2023; Magister et al., 2023).

## 4. Intent-grounded thinking (chat)

The preview mapped "kasto xa tw tmro swasthya" to an email address: it never worked out *what was asked*. Now, when a message is slangy or paraphrased, Nik's thinking starts by restating it in canonical form:

```
<|think|> bujheko: "timro swasthya kasto chha?" bhanne kura sodhnu bhayo. <|/think|> ...
```

The interpretation step is generated by the model and learned from paired noisy and canonical phrasings. It turns a hard many-to-one mapping into two easier steps: normalize, then answer. Chat-spelling noise (`xa`, `tw`, `tmro`, `v` for `bh`, …) covers how Nepali is really typed.

## 5. Self-consistency at inference

When Nik reasons and answers with a number, the browser samples up to 5 independent reasoning paths and keeps the majority answer (Wang et al., *Self-Consistency Improves Chain of Thought Reasoning*, ICLR 2023). Small models gain the most from this, because their errors are noisy rather than systematic. The UI shows the agreement ("5 bato · 4/5 sahamat"), so low agreement is an honest signal that Nik is unsure.

## 6. One network, two generators (SSBD)

The hybrid autoregressive / block-diffusion objective (see ARCHITECTURE.md) gives Nik a parallel drafting mode at no extra parameter cost. Self-speculative decoding is lossless: greedy SSBD output is verified token-for-token identical to greedy AR. It is most useful on GPU and WebGPU backends.

## 7. Size vs. compute

| | params | int8 | where it can be trained |
|---|---|---|---|
| nik-nano | 2.0M | 2.1 MB | CPU, minutes (preview only) |
| nik-small | 8.3M | 8.4 MB | single GPU, ~2 h |
| **nik-0.1** | 20.5M | 20.7 MB | single T4, ~4–5 h (Kaggle, resumable) |

The CPU previews show what each change does. The real reasoning quality comes from the GPU run. Track it with `python nik/eval.py`, which reports math exact-match, persona facts, perplexity and SSBD acceptance.
